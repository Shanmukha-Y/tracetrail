# Qwen evidence review for protocol v7

This is an assistant source review of Qwen's eight saved cells: adaptive and fixed search on four frozen synthetic cases. It is **not independent human review** and involved no additional Ollama inference. Reviewers compared saved queries, decisions, findings, declared field links and projected observations with exact fixture records. The [frozen protocol](../evaluation/protocol-v7.json) and [scalar results](../evaluation/results-v7.json) identify the experiment; this document makes no Gemma or Mistral comparison.

Adaptive produced three valid processes out of four; fixed produced four out of four. Process validity means the recorded structural checks passed, not that an investigation was complete or its prose correct. Citations and projected values resolved to their source records, including the retained report from the invalid process. Correct labels and resolvable citations do not establish complete support.

In [retention-chain](../fixtures/v6/dev-retention-chain.json), adaptive retrieved all three relevant records with two queries and linked all ten required annotation fields within the appropriate findings. Both credential joins and the requested 14-day retention value were supported. Fixed used three queries but retrieved only the seed: its time window excluded earlier caller activity and it did not follow the returned child key. Its uncertain answers describe that limited evidence, rather than demonstrating fabricated observations.

In [topic-denial](../fixtures/v6/dev-topic-denial.json), adaptive retrieved all three relevant records and correctly distinguished an explicit authorization denial from unknown intent and later resource state. Nevertheless, it claimed there was no remaining query budget after using only two of three queries. The machine stop reason correctly records voluntary finish. Its final findings are more careful than planning prose that treats absent error fields as proof a later read was not denied.

In [directory-path](../fixtures/v6/heldout-directory-path.json), adaptive retrieved caller, issuer and seed but declared the child-key **use** pivot tested by a query for credential **issuance**. Those are different predicates. Validation preserved `tested_pivot_requires_matching_successful_attempt`, making the process invalid. One query remained; an available child-use query could retrieve the later `GetUser`. The retained report covered six of eleven required field paths, but those report fields do not turn the invalid process into capability evidence.

In [trail-operations](../fixtures/v6/heldout-trail-operations.json), adaptive recovered the complete caller-to-issuer-to-seed credential chain, then stopped at three of four relevant records. It deferred an observed child-use pivot despite one unused query and overstated the missing status request as locally unavailable. That query could retrieve `GetTrailStatus`, although its null response still would not establish logging state. All four labels matched gold; support remained incomplete. Fixed retrieved the seed and status request while missing the caller and issuer.

AWS semantics matter here. Ordinary [read-only CloudTrail records](https://docs.aws.amazon.com/awscloudtrail/latest/userguide/cloudtrail-event-reference-record-contents.html) have null `responseElements`; a live API's state response is a separate source. [PutRetentionPolicy](https://docs.aws.amazon.com/AmazonCloudWatchLogs/latest/APIReference/API_PutRetentionPolicy.html) has an empty successful response body. Null alone is not failure evidence. API activity, recorded authorization outcomes and business approval also require separate interpretations.

The frozen scorer checks required atoms in the **global deterministic projection**, not each finding's declared links. For example, adaptive's trail caller claim passes despite omitting its explicit `eventName` link; fixed's state finding links only null while other required fields exist globally. Annotation scores therefore do not certify field-link completeness or narrative entailment. The local retention, topic, directory and trail review sidecars preserve canonical row hashes and counterexamples. These are single runs on invented data, with failures retained and no general winner established.
